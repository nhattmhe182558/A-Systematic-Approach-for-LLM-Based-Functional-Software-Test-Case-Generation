  Surveyed 19 real, net-new papers (~2025-2026) that appeared AFTER the prior published
  "Business Process-Centric Approach for LLM-Driven Functional Test Generation" (generation-only).
  The field has decisively moved from GENERATION to autonomous EXECUTION + verdict — i.e., the
  new paper's contribution. Author/venue details unconfirmed from snippets are marked [estimated];
  all arXiv IDs are real (26xx = 2026 preprints).

  KEY CLAIMS THE WRITER CAN MAKE (with citations):
  - Closest prior art on autonomous execution+verdict is "Are Autonomous Web Agents Good Testers?"
    (PinATA/SeeAct-ATA, arXiv:2504.01495): LLM Autonomous Test Agents execute NL test cases and
    return pass/fail verdicts (~60% correct verdict, up to 94% specificity). Differentiate IntelliTest
    by (i) business-process-grounded generation feeding execution, (ii) end-to-end integration,
    (iii) improved verdict reliability + self-healing.
  - Soundness/consistency of NL test execution is now a named problem (arXiv:2509.19136): NL tests
    are unsound (false failures from ambiguity) and inconsistent (nondeterministic re-runs) -> MUST
    appear in the execution half's threats-to-validity.
  - Self-healing & autonomous repair are active/measurable: DOM-accessibility-tree self-healing
    (arXiv:2603.20358, <1s selector re-discovery, zero API cost) and repair limits (arXiv:2605.01471,
    70% repair convergence, mean 4.4 iterations) -> use as feature + bounded-autonomy caveat.
  - DOM/accessibility-tree abstraction is a first-class execution concern: Prune4Web (arXiv:2511.21398)
    prunes 10k-100k-token DOMs; plus security risk via HTML accessibility-tree prompt injection
    (arXiv:2507.14799).
  - Oracle problem is unsolved: requirement->oracle alignment is weak/high-variance on real bugs
    (arXiv:2607.10277); multi-agent consensus oracles proposed (CANDOR arXiv:2506.02943). Argue for a
    consensus/requirement-grounded oracle and state accuracy caveats.
  - Multi-agent testing is now standard (ScenGen 2506.05079; CANDOR 2506.02943; TestAgent 2607.09101)
    -> the generation half is crowded; the DIFFERENTIATOR is the end-to-end generation->execution loop.
  - Story->executable UAT bridge exists (AutoUAT+Test Flow, arXiv:2504.07244: user story->Gherkin->Cypress).
  - Consider comparing against an agentic-testing benchmark: CAT (arXiv:2609.00081) + WebArena family.

  GAP THE NEW PAPER FILLS: No single 2025-2026 work combines (a) business-process/requirement-grounded
  functional test GENERATION with (b) an autonomous UAT EXECUTION agent (self-healing over a DOM
  abstraction, issuing reliable verdicts) while (c) empirically addressing soundness/consistency and
  oracle reliability. Prior IEEE Access work = (a) only. New contribution = integrated (a)+(b)+(c).
