**Test Scenarios for RetailOnboardPro System Testing**

---

**SCENARIO 1: Register Account – Success**
Steps:
1. Anonymous user navigates to Registration Page.
2. Enters valid full name, unique username, valid email, strong password (e.g., Abc@1234), matching confirm password.
3. Checks terms agreement checkbox.
4. Clicks ‘Register Account’.
Expected:
- New account created with default role ‘staff’.
- Success message displayed.
- User redirected to Login Page.

---

**SCENARIO 2: Register Account – Validation Errors**
Steps:
1. On Registration Page, leave required fields empty.
2. Enter invalid email, weak password (e.g., abc), mismatching confirm password, check no terms checkbox.
3. Click ‘Register Account’.
Expected:
- Registration blocked.
- Specific error messages displayed near invalid fields.
- Form remains populated with entered data.
- No account created.

---

**SCENARIO 3: Register Account – Duplicate Username/Email**
Steps:
1. Existing user credentials are present in system.
2. On Registration Page, enter existing username and email.
3. Complete all other fields correctly, check terms.
4. Click ‘Register Account’.
Expected:
- Error messages: “Username already exists” and “Email already exists”.
- No account created.

---

**SCENARIO 4: Login – Success**
Steps:
1. Anonymous user navigates to Login Page.
2. Enters valid username/email and password.
3. Clicks ‘Login’.
Expected:
- Credentials verified.
- Session created.
- Login attempt logged with user id and timestamp.
- User redirected to role-specific dashboard.

---

**SCENARIO 5: Login – Invalid Credentials**
Steps:
1. On Login Page, enter incorrect username/email or password.
2. Click ‘Login’.
Expected:
- Authentication fails.
- Failed attempt logged (username, IP, timestamp).
- Error message “Invalid username or password”.
- User remains on Login Page.

---

**SCENARIO 6: Logout – Success**
Steps:
1. Authenticated user clicks ‘Logout’ on any page.
Expected:
- Session invalidated.
- Client-side session identifiers cleared.
- User redirected to Login Page.

---

**SCENARIO 7: Manage User Profile – Update Contact Info**
Steps:
1. Authenticated user navigates to User Profile Page.
2. System displays current profile (name read-only, email, phone editable).
3. Modify phone number and/or other editable fields.
4. Click ‘Update Information’.
Expected:
- Validation passes.
- Users table updated.
- Update action logged.
- Success message “Profile updated successfully.”

---

**SCENARIO 8: Manage User Profile – Change Password**
Steps:
1. On User Profile Page, click ‘Change Password’.
2. Enter current password, new strong password, confirm new password.
3. Click ‘Save Changes’.
Expected:
- Current password verified.
- New password meets complexity (min 8, uppercase, lowercase, number).
- Password updated in users table.
- User logged out and redirected to Login Page for security.

---

**SCENARIO 9: Manage User Profile – Validation Errors**
Steps:
1. On User Profile Page, edit email to invalid format.
2. Change password to weak (e.g., “short”) or enter mismatched confirm password.
3. Click ‘Save Changes’ / ‘Update Information’.
Expected:
- Specific validation errors displayed.
- Profile not updated.
- Form retains entered data.

---

**SCENARIO 10: Create Training Request – Success**
Steps:
1. Staff logs in and navigates to Dashboard.
2. Clicks ‘Create New’ / ‘Create Training Request’.
3. System displays form with training category (dropdown) and reason (textarea), optional preferred dates.
4. Staff selects valid category and enters reason (≤1000 characters).
5. Clicks ‘Submit Request’.
Expected:
- Validation passes.
- Unique request_id generated.
- Record saved in requests table with user_id, request_type=’training’, status=’pending_manager’.
- Success message shows request ID.
- Redirected to “My Training Requests” list.

---

**SCENARIO 11: Create Training Request – Validation Failure**
Steps:
1. On Create New Training Request Page.
2. Leave training category and reason empty.
3. Or enter reason exceeding 1000 characters.
4. Click ‘Submit Request’.
Expected:
- Form submission blocked.
- Error message indicating required fields / max length.
- Form remains populated with entered data.

---

**SCENARIO 12: Create Training Request – Cancel**
Steps:
1. On Create New Training Request Page, enter some data.
2. Click ‘Cancel’ or browser Back Button.
Expected:
- Entered data discarded.
- User redirected to Dashboard or Request List Page.

---

**SCENARIO 13: Staff Views Own Training Requests – Success**
Steps:
1. Staff logs in and navigates to Dashboard.
2. Clicks ‘Training Requests’ / ‘View All’.
3. System retrieves requests where request_type=’training’ and user_id=current staff.
Expected:
- List displays request ID, training category, submission date, current status (exact status strings).
- Only requests submitted by this staff appear.
- If no requests, message “You have not submitted any training requests yet”.

---

**SCENARIO 14: Manager Processes Training Request – Approve**
Steps:
1. Manager logs in and navigates to ‘Manage Training Requests’.
2. System displays list of requests with status ‘pending_manager’ assigned to manager.
3. Manager selects a request, reviews details.
4. Clicks ‘Approve’.
5. Enter optional comments (or none).
Expected:
- Status updated to ‘pending_director’.
- Approval action logged with manager user_id and timestamp.
- Request removed from manager’s active queue.
- Success message “Training request [ID] approved and forwarded to director.”

---

**SCENARIO 15: Manager Processes Training Request – Reject**
Steps:
1. Manager selects a ‘pending_manager’ request.
2. Clicks ‘Reject’.
3. Provides mandatory rejection comments.
Expected:
- Status updated to ‘rejected_manager’.
- Rejection logged with manager user_id, timestamp, comments.
- Request removed from manager’s active queue.
- Success message “Training request [ID] rejected.”

---

**SCENARIO 16: Manager Processes Training Request – Already Processed**
Steps:
1. Manager opens a request in ‘pending_manager’ status.
2. Another manager/system updates the request to a different status.
3. Original manager clicks ‘Approve’ or ‘Reject’.
Expected:
- System detects request no longer in ‘pending_manager’ status.
- No status update performed.
- Appropriate message displayed.

---

**SCENARIO 17: Manager Views Training Request History – Success**
Steps:
1. Manager logs in and navigates to Dashboard.
2. Selects ‘View Training Request History’.
3. System retrieves historical requests within manager’s scope (team/department).
4. Manager selects a specific request to view audit trail.
Expected:
- List shows request details and status history.
- Detailed view includes all status changes, actors (staff/manager/director/hrhead), timestamps, comments.
- If none found, message “No training request history available”.

---

**SCENARIO 18: Director Manages Training Request – Approve**
Steps:
1. Director logs in and navigates to pending director approval section.
2. System displays list of requests with status ‘pending_director’ assigned/visible.
3. Director selects request, reviews full details and manager’s approval/comments.
4. Clicks ‘Approve’ and adds comments.
Expected:
- Status updated to ‘pending_hrhead’.
- Approval recorded in approval_history with director user_id, timestamp, comments.
- Request removed from director’s active queue.
- Success message “Training request [ID] approved and forwarded to HR head.”

---

**SCENARIO 19: Director Manages Training Request – Reject**
Steps:
1. Director opens a ‘pending_director’ request.
2. Clicks ‘Reject’ and provides comments.
Expected:
- Status updated to ‘rejected_director’.
- Rejection recorded with comments and timestamp.
- Success message “Training request [ID] rejected.”

---

**SCENARIO 20: Director Manages Training Request – Request Already Processed**
Steps:
1. Director opens a request in ‘pending_director’ status.
2. Another director/system updates the request.
3. Director clicks ‘Approve’ or ‘Reject’.
Expected:
- System detects request no longer in ‘pending_director’.
- Appropriate message shown, no update.

---

**SCENARIO 21: HRHead Manages Training Request – Final Approve**
Steps:
1. HRHead logs in and navigates to pending final approval section.
2. System displays requests with status ‘pending_hrhead’.
3. HRHead selects request, reviews full approval chain (manager, director).
4. Clicks ‘Final Approve’ and adds comments.
Expected:
- Status updated to ‘approved_final’.
- Final approval logged with HRHead user_id, timestamp, comments.
- Request removed from HRHead pending queue.
- Success message “Training request [ID] has been finally approved.”

---

**SCENARIO 22: HRHead Manages Training Request – Reject**
Steps:
1. HRHead opens a ‘pending_hrhead’ request.
2. Clicks ‘Reject’ and provides comments.
Expected:
- Status updated to ‘rejected_hrhead’.
- Rejection logged with comments and timestamp.
- Success message “Training request [ID] has been rejected.”

---

**SCENARIO 23: HRHead Manages Training Request – System Error During Update**
Steps:
1. HRHead attempts to final approve/reject a request.
2. Database error occurs during save.
Expected:
- Error logged.
- Changes rolled back.
- Generic error message displayed to HRHead.
- Request status remains unchanged.

Steps:
1. On Home Page, click ‘Login’ button.
2. On Login Page, click ‘Sign Up’ link.
3. On Registration Page, click ‘Back to Homepage’.

- User navigates to Login Page, then Registration Page, then back to Home Page.

**SCENARIO 25: Dashboard Navigation – Role-Specific Access**
Steps:
1. Staff logs in and sees Dashboard.
2. Click ‘Profile’ -> User Profile Page.
3. Click ‘Logout’ -> Login Page.
4. Login as Manager, see pending requests section.
5. Login as Director/HRHead, see their respective pending sections.
Expected:
- Each role sees only data/features authorized for that role.
- Unauthorized data not accessible.
